## 正文

你有没有想过，不用在手机上安装任何 App、也不用 root，就能在电脑浏览器里看到手机的**整块屏幕**，顺便用鼠标点、用滚轮滑、用按键操作它？

更进一步：在页面右下角打开聊天框，说一句「回到桌面」，手机真的就回到了桌面。

这不是科幻，是我们做的一个开源小项目：**Phone Screen Link**。今天不聊怎么装，聊聊它背后那套「四个模块、两个端口」的架构，以及几个我们反复斟酌过的取舍。

🎬【视频 1 · 待插入】开场演示：浏览器里整屏投屏 + 鼠标点击/滚轮 + 右侧按键 + 手机动作同屏（见附录 A-1）

### 一、先把边界画清楚，架构就容易懂了

这个项目从一开始就有三条硬边界：

- **不自研投屏协议栈**。视频、音频、触摸、滚轮、剪贴板，全部来自成熟开源引擎 `ws-scrcpy-web` v0.5.13。我们只做编排、封装和「最后一公里」的控制。
- **只在本机跑**。页面 `127.0.0.1:8000`，控制桥 `127.0.0.1:8100`。不 root、不装手机 App、不绕锁屏、不碰 `FLAG_SECURE` / DRM 内容。
- **聊天只是加法**。模型不接触设备权限，它只输出「工具名 + 参数」；真正动手的是 ghost 的 MCP 工具，而且必须先过后端白名单。哪怕模型挂了、ghost 起不来，投屏和按键照常工作。

换句话说，整个系统是一条「窄腰」：上面是浏览器，下面是手机，中间只有两个本地端口。所有跨进程、跨语言的交互，都被压到这两个接口上。

### 二、四个模块，各干各的

| 模块 | 干什么 | 不干什么 |
| --- | --- | --- |
| **引擎** | 视频解码、控制协议、WebCodecs | 我们自己的界面与安全策略 |
| **页面** | 设置、语言、无线面板、聊天面板 | 设备权限、模型调用 |
| **控制桥** | 按键/连接/聊天的唯一写入口 | 视频流 |
| **Agent 循环** | 锁屏门禁、白名单、工具编排 | 直接碰设备（交给 ghost） |

这里有个刻意的设计：`shared/` 目录里的按键码、语言包、设置校验、工具白名单，**浏览器和 Node 共用同一份代码**。前端改了语言包，后端校验规则不会悄悄漂移。因为引擎的静态服务器不认 `.mjs`，启动时会把这些文件改名复制成 `.js` 再交给引擎——一个很小但必须处理好的细节。

### 三、投屏：站在巨人肩上，但仍要动刀

引擎拉起后，页面调用它的 `startStream()` 就拿到了视频流和触摸通道。我们自己不建 WebSocket，只处理四个回调：连接、断开、错误、尺寸变化。

但「直接用上游」有两个问题：它默认监听所有网卡；它的音频播放器在 worklet 加载失败时会静默没声音。

我们的做法不是 fork 一份引擎，而是**在 `npm run setup` 阶段打一组可重放补丁**：

- 把 `server.listen(port)` 改成只监听 `127.0.0.1`——整个项目的安全前提；
- AudioWorklet 加载超过 1.5 秒或失败时，自动回退到 `ScriptProcessorNode`，并修掉停止时的竞态；
- 输入框获得焦点时不把键盘事件转发给手机，滚轮倍率可调；
- 为 macOS arm64 补齐 Node / adb / node-pty 的下载映射。

补丁采用「锚点字符串替换」：如果源码里找不到预期锚点，直接报错而不是静默跳过。**上游升级只剩改一个 tag 常量**，但一旦漂移，构建会立刻告诉你。

### 四、控制桥：所有写操作都从一个端口进

视频走引擎的 WebSocket，但按键、连接、聊天这些「写操作」全部收拢到 `8100` 端口的控制桥。接口面很小：`/health`、`/keyevent`、`/api/wireless*`、`/chat`、`/api/chat-config`。

安全上做了几件听起来朴素、但很关键的事：

- 服务只绑回环地址，CORS 只允许 `127.0.0.1:8000` 和 `localhost:8000`；
- **所有 POST 都强制校验 Origin**。CORS 只拦「读响应」，恶意网页仍能发免预检的简单请求来改配置、驱动手机，所以白名单外的 Origin 一律 403，请求体根本不读；
- 请求体上限 64KB；配对码必须是 6 位数字，错误响应里会脱敏；
- `/chat` 只读 `message` 和 `lang`，你在请求体里塞什么开关、什么模型地址，一律忽略。

把「看」和「写」拆成两条物理通道，是「聊天坏了不影响投屏」的真正保证。

### 五、拔掉 USB 之后：两种无线模式

默认从 USB 开始，但项目支持两种无线方式：

- **Android 11+ 配对码模式**：通过 USB 自动读手机 Wi-Fi IP 和连接端口，再从 mDNS 找配对端口（最多等 8 秒），你只需手输 6 位配对码，应用执行 `adb pair` → `adb connect`，确认在线后才切换；
- **传统 5555 模式**：给没有配对码弹窗的设备（比如 EMUI）。点「自动获取并连接」，应用先读 IP，再由**这次点击**触发 `adb tcpip 5555`，然后连接。传统模式**未加密、无认证，仅限可信局域网**，面板里会一直显示醒目的警告。

这里有两个我们很在意的细节。

第一，**切换是串行且原子的**：配对、传统连接、切回 USB 都进同一个事务队列；先证明目标在线，再写盘，磁盘写成功才切换活动设备。任何一步失败，运行时和磁盘都保持原样。

第二，**无线模式下不再枚举 USB**。后台每 5 秒只对你保存的无线地址做 `get-state`，离线就重连这个地址。传统模式如果要恢复被重启的 adbd，用一次性的引导键加 250/500/1000ms 的有界退避——不会每 5 秒重启一次 adbd。这个设计来自一台真机上的坑：`adb tcpip` 之后 EMUI 的 adbd 要一两秒才起来，立即 connect 会被拒绝。

而那个传统模式的安全警告，**以后端实际使用的 `method` 为准，不以浏览器里选的选项为准**。哪怕你清空了浏览器存储、或者另一个浏览器配置还停在配对模式，只要后端正在用传统模式，警告就一定显示。

### 六、让大模型替你点手机

右下角的聊天按钮，是这个项目最像「AI Agent」的部分。整条链路是：

> 一句话 → 后端检查配置与锁屏状态 → 从 ghost 拉取真实工具定义 → 过滤出 15 个白名单工具 → 交给 OpenAI 兼容模型做 tool calling → 后端校验工具名和参数 → ghost 执行 → adb 操作手机 → 把结果和截图回灌给模型 → 气泡里显示回复和「工具 ✓/✗」。

几个刻意的安全取舍：

- ghost 只是**工具层**。模型拿不到 ADB，只能说「我要调 tap，参数是 x=300, y=600」。后端把设备序列号强制注入每次调用，模型没法把操作指向别的设备；
- 白名单只留 15 个安全工具（点击、滑动、输入、启动应用、截图、界面层级读取等），**明确拒绝** `shell`、安装/卸载、文件推送拉取、读剪贴板、解锁设备；
- 锁屏状态的真相源在后端：用 ADB 读 `dumpsys power` / `dumpsys trust`，读不到就**按锁定处理**，锁定时模型和动作工具都不调用；
- 每次模型调用限时 60 秒，单次最多若干步；API Key 只写不回，界面上是密码框。

要说清楚的是：截图默认开启，屏幕文字和截图会发往**你自己配置的**模型地址。不想外发就关掉开关，或者把模型服务放在你自己的局域网里。另外，目前每轮对话是无状态的——面板气泡仅供阅读，模型看不到历史。这是明确的取舍，不是 bug。

### 七、启动与停止：别小看这两条命令

`npm start` 背后其实做了不少事：先解析连接模式（环境变量 > 持久化配置 > 默认 USB），再复制页面资源、启动引擎、以 25 秒为限拉起 ghost、启动控制桥、最多等 30 秒引擎就绪，最后挂上每 5 秒一次的连接监督。

缺 adb？不致命——引擎会在后台下载自带的那份，启动脚本只打印提示并继续。ghost 起不来？只禁用聊天，投屏照常。

退出同样是门学问：信号处理、失败路径、正常结束都会走同一个可重入的 `cleanup()`，桥 → ghost → 引擎子进程依次释放，每一步都有超时兜底。对应的 `npm run stop` 只精确匹配**本项目目录**下的进程，先 `SIGTERM`、最多等 5 秒，再对幸存者 `SIGKILL`，不会误杀你另一个 checkout。

🎬【视频 5 · 待插入】终端录屏：`npm start` → 日志出现 bridge listening → 浏览器刷新看到已连接 → `npm run stop` → 端口关闭（见附录 A-5）

### 八、400 个测试，和一个诚实的缺口

项目现在有 **400 个 Node 单元测试 + 22 个 Python 安装向导测试**。它们用注入的假依赖跑，不碰真机、不起 ghost、不发真实模型请求。行为改动走 RED → GREEN：比如「安全警告以后端 method 渲染」这个修复，是先写了 3 个失败的前端用例再实现的。

但我们不把没做的事说成做了：ghost 的真实返回结构、模型驱动手机完成一整轮操作的**真机冒烟尚未执行**。已有的真机证据是传统 5555 模式连接成功、页面显示「已连接 — 522x1080」、安全警告可见。剩下的清单写在项目 README 里，谁配好模型后端都可以照着打勾。

### 最后

回头看，这个项目的架构价值不在某个算法，而在**边界感**：把第三方的大块能力关在各自的进程里，用两个本地端口串起来；凡是涉及设备权限、模型输出和安全提示的决定，一律收拢到后端；并且让「降级」成为默认容错策略。

这样一套由多个开源组件拼起来的系统，仍然能被 400 多个注入式测试稳稳锁住。
