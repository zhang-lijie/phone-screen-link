## 1. 背景与目标

在一台电脑上实时查看并操作华为 Mate 40 Pro 的**整台屏幕**（不是单个 App 的截图），并在网页上完成 Home / Back / 多任务 / 电源 / 音量等反控操作，网页与手机状态实时联动。
第一版之后追加：**用自然语言控制手机** —— 页面右下角对话按钮 + 聊天面板，由局域网上的 OpenAI 兼容大模型选工具，经后端白名单校验后通过 ghost-in-the-droid 的 MCP 工具执行点击、输入、启动应用等，把自研桥 6 个按键之外的能力接进来。

核心取舍：**复用成熟开源项目做二次开发，不自研投屏协议栈**；第一版只在本机 `http://127.0.0.1:8000` 运行，架构上预留远程扩展但本期不实现；不 root、不绕过锁屏、不采集 `FLAG_SECURE` / DRM 内容、不在手机安装额外 App。
聊天的取舍：ghost 只当**工具层**，agent 循环、模型调用、白名单与安全门禁全部自己写（设计文档方案 B），模型不接触设备权限；旧桥 `/keyevent` 明确不动，聊天坏了不影响投屏。

## 3. 功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-01 | 整屏镜像 | 手机全屏画面实时投到浏览器；视频/音频与控制走 WebSocket |
| FR-02 | 系统按键反控 | 电源、音量±、返回、主页、多任务；最初在顶部文字栏，后按用户要求隐藏顶栏，统一到右侧工具栏 |
| FR-03 | 触摸反控 | 鼠标点击/拖拽等价于手指触摸，触摸层与画面严格重合 |
| FR-04 | 滚轮与右键 | 滚轮上下滚动手机页面；右键映射 Back，浏览器原生菜单被禁止；Esc 可退出全屏 |
| FR-05 | 设置面板 | 分辨率、帧率、码率、音频、显示语言、界面字体大小/颜色、统计字体大小/颜色、导航条最大尺寸、状态条最大尺寸、导航按钮显示 |
| FR-06 | 分辨率自适应 | 请求 1280 → 1080 → 720 阶梯；检测协商分辨率被大幅降级时自动重启并降一档 |
| FR-07 | 多语言 | 中文/英文；"跟随浏览器"按 `navigator.language` 的 `zh` 前缀判断；静态文本、状态、锁屏/剪贴板提示、tooltip、canvas 统计文字全覆盖 |
| FR-08 | 状态联动 | 每 3 秒轮询设备锁屏/休眠状态，黑屏时给出明确提示 |
| FR-09 | 画面全屏 | 画面左上角图标按钮（tooltip 提示），点击后 `#stream` 铺满视口并隐藏工具栏；画面圆角、白边、间隔保留；再次点击或 Esc 退出 |
| FR-10 | 外观 | 画面圆角 20px、2px 白色描边、上下 2px 间隔；外侧容器无边框/圆角/阴影 |
| FR-11 | 工具栏 | 引擎工具（截图/键盘/鼠标/统计/刷新/复制/粘贴/设置）带文字标签；按键显示模式可为图标/文字/图标&文字；统计与触控位置已交换 |
| FR-12 | 引擎工具 | 截图、键盘捕获、UHID 鼠标键盘、画质统计、触控/方向键切换、刷新、剪贴板双向 |
| FR-13 | 启动编排 | USB 唯一性检查与周期复查、复制 web 资源、启动引擎与桥、就绪等待、信号清理 |
| FR-14 | 反馈与错误处理 | 连接中/已连接/按键已发送/离线/引擎不可用/不安全来源等状态提示 |
| FR-15 | 对话控制手机 | 右下角常驻圆形按钮（tooltip 随语言），仅在后端 `enabled` 为真时显示（模型名为空时图标仍显示，但后端 503、面板给可读提示）；点开聊天面板，输入中英文自然语言，经模型 tool calling → 白名单校验 → ghost 执行，回复与 `工具 ✓/✗` 步骤标签回显为气泡；执行期间锁输入并显示「正在执行…」；提供 `清空对话` 与 `×`/`Esc` 收起 |
| FR-16 | 聊天配置后端持久化 | 设置面板「聊天」分组 6 项（`enabled`/`baseUrl`/`model`/`apiKey`/`screenshot`/`maxSteps`），经 `GET/POST /api/chat-config` 读写，落 `state/chat.json`；不信任请求体里的开关，`/chat` 只读 `message` 与 `lang`；API Key 不回传前端（只回 `hasApiKey`），留空表示保持原值；保存聊天不重启画面流 |
| FR-17 | 工具白名单与参数校验 | 运行时从 ghost `tools/list` 拉 schema，过滤出 15 个工具（5 读 / 9 操作 / `screenshot`）暴露给模型；明确拒绝 `shell`、`install`、`uninstall`、`push`、`pull`、`clipboard_get`、`unlock_device`；名单外或参数非法一律不执行并在聊天里说明；`screenshot` 受配置开关约束；单次请求最多 `maxSteps` 轮 |
| FR-18 | ghost 工具层接入 | 以 stdio MCP 子进程启动 `uvx --from ghost-in-the-droid android-agent-mcp`，用 `DEFAULT_DEVICE` 选中固定 USB 序列号；`npm run setup` 检测 `uvx`/`uv` 缺失只提示不阻断；ghost 启动失败则聊天禁用，投屏与 `/keyevent` 不受影响；退出时随桥、引擎一起清理 |

## 4. 非功能需求

| 编号 | 需求 | 实现要点 |
| --- | --- | --- |
| NFR-01 | 安全边界 | 引擎与桥只绑定 `127.0.0.1`；桥 CORS 白名单仅 `http://127.0.0.1:8000` 与 `http://localhost:8000`；启动强制断开 Wi-Fi ADB，只认固定 USB 序列号 |
| NFR-02 | 设备与内容限制 | 不 root、不绕过锁屏、不采集 `FLAG_SECURE`/DRM、不安装手机 App；锁屏黑屏只做解释性提示 |
| NFR-03 | 清晰度 | 实测设备屏幕 1152×2376，编码器请求过大时会回退到 512 上限；关闭 `fitToScreen`，显式请求尺寸并按阶梯降级 |
| NFR-04 | 启动健壮性 | 代理环境下 Node `fetch` 不读系统代理，可选 node-pty 下载会超时；启动脚本注入 `NODE_USE_ENV_PROXY` 与 `--use-system-ca` |
| NFR-05 | 浏览器兼容 | WebCodecs 需要安全上下文，普通 HTTP 仅 loopback 可用；`.mjs` 静态服务不支持，浏览器侧统一复制为 `keys.js` |
| NFR-06 | 可维护性 | 引擎作为 GPL-3.0 外部依赖由 `setup` 拉取、不入库；ghost 作为 MIT 上游同样不入库、运行时由 `uvx` 解析；按键码、设置校验、分辨率策略、语言包集中在 `shared/keys.mjs`，工具白名单集中在 `shared/chat-tools.mjs`；115 个单元测试 |
| NFR-07 | 易用性 | 设置改动立即生效；tooltip 与文字标签双语；状态栏实时反馈；README 含快速开始、排错与截图 |
| NFR-08 | 聊天安全边界 | 模型只拿到白名单内的工具名与参数，不接触 ADB；`/chat` 与 `/api/chat-config` 复用桥的回环绑定与 CORS 精确白名单，不新增端口、不放宽来源；锁屏真相源是后端 `get_phone_state`，读不到按锁定处理（fail closed），不尝试解锁 |
| NFR-09 | 聊天隐私 | 屏幕文字与**截图（默认开启）**会发往用户自填的模型地址，README/界面文案已明示；剪贴板只读不暴露；API Key 只进不出（存 `state/chat.json`、只出现在请求头），前端输入框为 `password` |
| NFR-10 | 聊天隔离性 | 聊天是新增入口，与 `/keyevent`、投屏、触摸、滚动互不依赖；ghost 未装/起不来、模型超时或返回畸形 tool_calls 只影响聊天气泡，桥与引擎照常服务（由启动编排与桥的测试锁定） |

## 5. 约束与限制

- 设备与端口固定：USB 序列号 `2FD0221C09004177`，引擎 `8000`，桥 `8100`；换设备需改 `server/adb.mjs` 与 `web/app.js`。
- 引擎是第三方 GPLv3 项目，版本锁定 v0.5.13，仅有 loopback 补丁；升级需改 `ENGINE_TAG` 并重建。
- 远程访问未实现；LAN 上普通 HTTP 无法解码视频，需要自行加 HTTPS 并放宽 CORS/绑定。
- 无进程守护，由启动脚本自己处理清理；`web/`/`shared/` 改动需重启 `npm start` 才会复制。
- 设备编码器的可接受尺寸上限会随状态变化；1280 有时可用、有时必然降级，因此保留自动阶梯而非固定值。
- 聊天需要本机额外工具链：Python 3.10+、`uv`/`uvx`、`PATH` 中的 `adb`，以及支持 function/tool calling 的 OpenAI 兼容端点；缺任一项只有聊天不可用。
- ghost 包版本不固定（`uvx` 每次解析上游），工具名与返回结构属于外部契约；本项目只在 Node 侧做浅校验，不做完整 JSON Schema 校验。
- 本机开发环境有 `uvx`、`adb` 和连着的 Mate 40 Pro，但**没有可用且开启 tool calling 的模型端点**，因此聊天的**真机冒烟未执行**，详见第 7、8 节。

## 6. 最终界面形态

- 顶部导航栏隐藏；系统按键与工具集中在右侧 44px（可倍数调整）窄栏，按钮可切换图标/文字/两者。
- 秩序：电源、音量+、音量−、返回、主页、多任务、截图、键盘、鼠标、**触控、统计**、刷新、复制、粘贴、设置；左上角为全屏图标按钮。
- 画面：圆角矩形 + 2px 白色描边 + 上下 2px 间隔；外侧容器为普通黑底，无边框、圆角、阴影。
- 语言：默认跟随浏览器；中文界面下所有按钮、tooltip、状态与统计文字均为中文。
- 聊天：右下角一个圆形对话按钮（后端未启用时不渲染），点开是近黑底 + 冷蓝强调色的聊天面板，助手气泡下方带 `工具 ✓/✗` 步骤标签，底部为 `清空对话`；配置项在设置面板的「聊天」分组里单独保存，不与 `localStorage` 设置混在一起。

## 8. 已知遗留与后续方向

**已实现（第一版之后追加）**

- **对话控制手机（Chat Agent）**：右下角对话按钮与聊天面板、6 项聊天配置后端持久化（`state/chat.json`）、
  工具白名单与参数校验、agent 循环（锁屏 fail-closed 门禁、越权拒绝、截图按视觉消息回灌、最大步数）、
  ghost stdio MCP 工具层、`POST /chat` 与 `GET/POST /api/chat-config`、双语聊天文案。
  旧桥 `/keyevent` 与右侧按钮、投屏、触摸/滚动、设置面板均未改动，聊天只做加法。

**遗留小问题（不阻塞第一版）**

- `lockHint` 的"正在唤醒"文案尚未接 `POST /api/devices/sleep-wake`，目前只是提示。
- 按键处理可能覆盖错误状态（工具条与状态栏的提示优先级）。
- 轮询失败时旧的锁屏提示可能残留。
- `copyWeb` 用文件列表最后一项推断共享文件、子进程缺少 `'error'` 监听、readiness `fetch` 无 `AbortSignal` 等实现细节可加固。
- **聊天没有真正的多轮上下文**：设计文档 §5.2 写过"保留最近若干条上下文"，当前 `/chat` 契约是每条消息无状态
  （后端只拼 `[system, 当前这句]`），面板气泡仅供阅读。要兑现该条需给契约加历史字段 —— 已按本版本范围明确降级为后续项。
- **API Key 无法从面板清除**：留空语义是"保持不变"（`publicConfig` 不回传 Key），要清除只能编辑 `state/chat.json`；
  后续可加"清除已保存的 Key"复选框。
- 聊天面板 `z-index` 高于设置面板遮罩，两者同时打开时面板仍可点击（为了在全屏画面上仍能用），观感可再调。
- `web/app.js` 里聊天段落约 220 行内聚但仍在主文件；拆成 `web/chat.js` 要同时改 `scripts/start.mjs` 的 `copyWeb` 文件列表与其测试，本轮未做。
- 参数校验只做必需字段与基本类型；ghost 包版本未固定，上游改名会影响聊天（有测试锁定本项目侧契约，真机冒烟欠执行）。

**后续方向**

- 远程访问（HTTPS + CORS/绑定地址放宽 + 鉴权）。
- 多设备切换与设备发现 UI。
- 真实浏览器 Fullscreen API（当前为 CSS 铺满视口的等价实现）。
- 手机端配套 App（当前明确不安装额外 App）。
- 更完整的自动化测试（DOM 层与端到端截图对比）。
- 聊天的多轮上下文（`/chat` 加历史字段）、Key 清除入口、按消息流式返回、锁定 ghost 版本并加形状快照测试。
