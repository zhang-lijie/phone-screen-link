# macOS arm64 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Apple Silicon (darwin-arm64) users complete the one-click install and run the app; Intel Mac stays explicitly unsupported.

**Architecture:** Three vendored-engine source patches declared in `scripts/setup.mjs` (Node darwin-arm64 bootstrap, adb darwin archive, prebuilt platform tag) applied via the existing idempotent `applyPatch` mechanism, plus platform-gate relaxation in `install.sh` and the Python wizard detector. No changes to the mirroring core; GPL boundary unchanged.

**Tech Stack:** Node ESM patches, Python stdlib, POSIX shell, `node:test`, `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-23-macos-arm64-design.md`

## Global Constraints

- Only darwin-arm64 is supported; darwin-x64 must be rejected with a clear message (no upstream node-pty darwin-x64 prebuilt — verified 404).
- Engine is gitignored and external; every engine edit must be a patch constant in `scripts/setup.mjs` with `applyPatch` (idempotent, loud on anchor drift).
- Node archive: `node-v24.19.0-darwin-arm64.tar.xz`, SHA256 `3f1cf157479c1480352083105e13faf9d008ede98e7e157746b6df940d197b94`, inner `node-v24.19.0-darwin-arm64/bin/node`.
- adb archive: `platform-tools_r<version>-darwin.zip` (Google publishes it — verified 200).
- node-pty prebuilt: `...-darwin-arm64` exists for ABI 137/139 (verified 200); engine-pinned Node v24.19.0 = ABI 137.
- Linux x64 behavior must remain unchanged.
- No Mac available locally: real-device setup/projection/audio verification is out of scope and must be documented as a limitation.

## Review Focus

- Intel Mac (darwin-x64) must be rejected clearly, not fail late — Task 2 installer tests.
- `getPlatform()` and `adbArchiveName()` both hardcode linux; patching only one leaves adb broken — Task 1 patch tests cover both anchors.
- `applyPatch` anchor drift on upstream engine bump must fail loudly — covered by Task 1 using exact anchors.
- Linux x64 path unaffected by darwin branches — Task 1 full suite + Task 2 suite.
- Node darwin SHA256 must be the exact published value (wrong hash breaks setup silently) — pinned in Task 1 test.

### Task 2: Installer platform gates accept darwin-arm64

**Files:**
- Modify: `install.sh`, `installer/server.py`
- Test: `tests/installer_test.py`

**Interfaces:**
- Consumes: nothing new.
- Produces: `detect_environment()` now accepts `platform_name="darwin", machine="arm64"`.

- [ ] **Step 1: Write failing tests** in `tests/installer_test.py`:
  - `test_detect_accepts_darwin_arm64`: `detect_environment("/usr/bin", "darwin", "/x", machine="arm64")` → `supported=True`, reason empty.
  - `test_detect_rejects_darwin_x64`: `machine="x86_64", platform_name="darwin"` → `supported=False`, reason mentions `arm64`.
  - `test_install_sh_accepts_darwin_arm64`: run `install.sh` with `PHONE_SCREEN_LINK_DRY_RUN=1` and a stubbed `uname` earlier in PATH returning `Darwin`/`arm64` → exit 0 and output contains `安装目录`.
  - `test_install_sh_rejects_darwin_x64`: stub `uname -m` returns `x86_64` on Darwin → exit != 0, output mentions `arm64`.

- [ ] **Step 2: Run** `python3 -m unittest discover -s tests -p 'installer_test.py' -v` → FAIL.

- [ ] **Step 3: Relax gates.**
  - `install.sh`: accept `uname -s` in (`Linux`, `Darwin`); for `Darwin` require `uname -m == arm64` else error mentioning arm64; keep Linux requiring `x86_64|amd64`.
  - `installer/server.py`: `supported = (platform_name == 'linux' and x64) or (platform_name == 'darwin' and machine == 'arm64')`; reason message updated to mention both accepted platforms; keep `x64`/`arch` fields.

- [ ] **Step 4: Run** `python3 -m unittest discover -s tests -p 'installer_test.py' -v` → all pass.

- [ ] **Step 5: Commit** `git add install.sh installer/server.py tests/installer_test.py && git commit -m "feat: accept darwin-arm64 in installer platform gates"`.
