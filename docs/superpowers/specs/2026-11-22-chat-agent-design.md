# 聊天控制手机（Chat Agent）设计

日期：2026-11-22
状态：待用户确认

## 1. 意图与原因

用户要在页面右下角加一个对话图标，点开是聊天框；用自然语言说一句话就能控制手机（"回到桌面""打开设置""音量调大""点一下允许"）。动机是现有按钮入口能力有限——自研桥只有 6 个按键，想用大模型 + 开源 agent 把能力扩展到点击、输入、启动应用等。

结论（已与用户确认）：接**局域网部署的 OpenAI 兼容大模型**；用开源项目 **ghost-in-the-droid/android-agent** 做设备工具层；**agent 的循环由我们自己写**（不采用 ghost 自带的循环）；自研桥退场，不把业务代码塞进引擎。

## 2. 目标 / 非目标 / 反目标

**目标**

- 右下角常驻对话图标，点开聊天面板，输入中英文自然语言控制手机。
- 模型通过 tool calling 选工具，我们校验白名单后调用 ghost 执行，结果回显为聊天消息。
- 复用现有设置面板、多语言、状态反馈体系。

**非目标**

- 不做手机端 App，不 root，不绕过锁屏。
- 不在本期实现远程访问（模型在局域网，但页面仍只绑本机）。
- 不替换 ws-scrcpy-web 投屏。

**反目标（要避免）**

- 模型或 agent 直接持有设备权限、绕过白名单。
- 把手机画面/剪贴板默认发给模型。
- 聊天功能坏了影响现有投屏和按钮控制。

## 3. 约束

- 现有边界：引擎与桥只绑 `127.0.0.1`；WebCodecs 要求安全上下文；改 `web/`/`shared/` 需重启 `npm start`。
- 设备固定 USB 序列号 `2FD0221C09004177`；不装手机 App。
- 大模型必须走用户局域网的 OpenAI 兼容 `/v1/chat/completions`，支持 function/tool calling。
- ghost 是 Python 项目，通过 stdio MCP server 暴露工具；本机需要 Python/uv 环境。

## 4. 方案取舍

| 方案 | 做法 | 取舍 | 结论 |
| --- | --- | --- | --- |
| A | 用 ghost 自带 agent 循环，直接连模型 | 省事、规划能力强；但黑盒、越界难控，且要适配它的前端/会话与我们打通 | 否 |
| B | ghost 只做 MCP 工具层，agent 循环、模型调用、白名单全由我们写 | 多写 Node 侧 MCP client 和约百行循环；边界完全在我们手里，出错好查，复用现有体系 | **选 B** |
| 附：把桥整合进引擎 | 给引擎加 ApiHandler 挂 `/keyevent` | 少一个端口；但业务代码进第三方 GPL 项目，升级补丁链脆弱，且桥本来就要退场 | 否 |

## 5. 设计（已决定部分）

### 5.1 分层与数据流

```
页面右下角聊天 UI（我们写）
  └─ POST /chat  →  Node 聊天后端（并入现有 start.mjs 进程，占用 8100）
       ├─ 调局域网模型 /v1/chat/completions（带 tools 定义）
       ├─ 解析 tool_calls → 白名单校验
       ├─ MCP client（stdio）→ ghost 的 MCP server → ADB → 手机
       └─ 工具结果回灌模型，循环直到最终文本回复，回显聊天框
```

进程形态：现有编排进程（Node）内新增聊天 HTTP 服务与后端配置存储；spawn ghost 的 stdio MCP server 作为子进程；引擎进程独立不变。自研 `server/bridge.mjs` 的 `/keyevent` 继续供现有按钮使用、不做改动；聊天是另一条经 ghost 的路径，两者互不依赖。

### 5.2 聊天 UI

- 右下角固定圆形按钮（对话图标，带 tooltip，随语言切换）；点击展开/收起面板。
- 面板包含消息列表（用户/助手气泡）、输入框、发送按钮，样式沿用近黑底 + 冷蓝强调色。
- 执行中显示"正在执行…"状态；模型/工具失败显示可读错误，不静默。
- 支持多轮对话，保留最近若干条上下文；提供"清空对话"。
- 全部文案进语言包，中英文一致。

### 5.3 模型与配置

设置面板新增分组（聊天）。**配置持久化在 Node 后端**：设置面板读写后端接口，API Key 不进前端；「启用聊天」「模型名为空则禁用」由后端强制校验，不信任客户端传来的开关。

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用聊天 | 关 | 关闭时右下角图标不显示，不发起任何模型请求 |
| 模型服务地址 | `http://127.0.0.1:11434/v1` | OpenAI 兼容 base URL |
| 模型名 | 空 | 需用户填写；留空则聊天禁用并提示 |
| API Key | 空 | 可选，局域网模型通常不需要 |
| 截图发给模型 | 开 | 用户确认允许截图发给局域网模型；向模型暴露 `screenshot` 工具，按视觉消息格式回灌 |
| 单次最大步数 | 8 | 防止 agent 循环失控 |

### 5.4 工具白名单

从 ghost 的 66 个工具里只暴露一个子集给模型：

- 读：`dump_ui`、`get_screen_tree`、`get_phone_state`、`list_apps`、`find_on_screen`
- 操作：`tap`、`tap_element`、`swipe`、`type_text`、`press_key`、`press_back`、`press_home`、`launch_app`、`clipboard_set`
- 截图：`screenshot`（默认开启，用户已确认允许发给局域网模型）
- **明确排除**：`shell`、`install`、`uninstall`、`push`、`pull`、`clipboard_get`、`unlock_device`（不绕锁屏、不给任意命令权限）

任何模型返回的不在白名单内的工具名，后端拒绝执行并在聊天里说明。

### 5.5 安全与隐私

- 模型只拿到工具名和参数，不接触 ADB 连接；设备操作全经 ghost，且受白名单约束。
- 截图允许发给用户自己配置的局域网模型（默认开启）；剪贴板读取仍不暴露。
- 锁定/休眠状态沿用现有轮询：若手机锁定，agent 不尝试解锁，只回复提示。
- 模型请求带超时；任一环节失败回显错误，不影响投屏和其他控制。

### 5.6 多语言

- 聊天气泡、按钮、状态、错误文案进语言包。
- 发给模型的 system prompt 按当前语言生成同一意图的中/英版本，要求模型用相同语言回复。

## 5.7 reviewer 提出的问题中由实现者拍板的部分

- **锁屏/休眠状态的真相源**：后端每次通过 ghost 的 `get_phone_state` 自行判断，不信任前端上报；前端轮询的状态只用于界面显示。这样锁定状态的拦截在后端可靠执行。
- **工具 JSON Schema 的来源**：运行时从 ghost MCP server 的 `tools/list` 拉取，按白名单过滤后同时用于发给模型的工具定义和后端参数校验；不手写固定 schema，避免与 ghost 版本漂移。拉取失败时聊天报错并禁用，不静默降级。
- **截图回灌格式**：用户已确认截图可以发给局域网模型，故 `screenshot` 默认开启，工具结果按 OpenAI 视觉消息格式（`image_url` 的 base64 data URI）回灌。模型不支持视觉输入时由模型/后端报出可读错误，不做预先能力探测。

## 6. 留给实现者（builder）的决定

以下属于实现细节，按现有项目风格自行决定，不必回问用户：

- 聊天面板的具体尺寸、动画、是否可拖拽。
- MCP client 用哪个 Node SDK、stdio 子进程的生命周期管理细节。
- ghost 的安装方式（npm setup 时检测 Python/uv 并给出提示或自动安装），以及在 README 里写清前置条件。
- 消息历史的长度上限、超时具体数值、错误文案措辞。
- 会话是否跨页面刷新保存（建议不保存，刷新即清空）。
- 测试范围：白名单校验、配置校验、模型响应解析（含 tool_calls）、语言包完整性、UI 基本交互。

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 模型返回畸形/越权工具调用 | 后端强校验白名单 + 参数 schema，拒绝即回显 |
| agent 循环卡住 | 最大步数 + 每步超时 |
| ghost 环境缺失或启动失败 | 启动时检测，聊天里给出明确提示；不影响投屏 |
| 截图/文字外发到模型 | 默认关闭截图、API 地址由用户填局域网地址；README 明示数据流 |
| 聊天功能与现有入口冲突 | 聊天只是新增入口，按钮/工具栏不删除，互不依赖 |
